# MySQL上でのトランザクション操作の原子性保証について

## 検証対象のOSS
引き続きMySQLについて．  
ただしこの章においてはテーブルスキーマは抽象化し，レコードのトランザクション操作のみについて考える．
すなわち，トランザクション内で「一部のレコードだけが変更されるが一部だけが変更されない」という中途半端な結果が存在しない．

## 検証すべき性質
MySQL上のInnoDBストレージエンジンがデータベスのACIDモデルに厳密に準拠していることは公式的に明記されている．  
ここでそのうちのA: Atomic(原子性)について，その性質を検証してみる．
* 原子性について
1つのトランザクションに含まれるすべてのレコードは，同一の状態を持つ.


## モデル化
本モデルでは，トランザクションとレコードを以下のように定義する．
* 各トランザクションは，
  - 1つ以上のレコード集合を操作対象として持つ
  - 実行結果として 1つのコミット状態を持つ
*各レコードは，
  - 「変更された」または「変更されていない」のいずれかの状態を持つ
 
トランザクションの結果は次の3種類としてモデル化する.
*Committed：正常に完了し，変更が確定した状態
*RolleBacked：失敗し，変更がすべて取り消された状態
*Partial：一部のみが反映された中途半端な状態（本来は存在しない状態）

そしてfactにより，
* トランザクションがCommittedの場合，そのトランザクションが操作した すべてのレコードは「変更された」状態になる
* トランザクションが RolleBackedの場合,そのトランザクションが操作した すべてのレコードは「変更されていない」状態になる(失敗したトランザクションでは，対象レコードに対する変更は一切残らない)

##検証手法
原子性の性質を形式化し，`assert AtomicityHolds`に書き下した．<br>
これによりcheckの検査を行うと，制約が十分なときは反証が出てこなかった． <br>
一方一部の制約をなくしたり変更するといくつかの反証が示された．
